# G4 — homologação automatizada e entrega autovalidada

## Executar no host de homologação (um comando)

Requisitos já presentes no host do G2: bash, git, Docker Engine + Compose v2, curl, ss. Nada é instalado. Usuário normal do grupo `docker`.

```sh
cd ~/sandboxes/agent/projects/catus-os-m5 && deploy/g4.sh
```

Enquanto esta branch não estiver integrada, rode a versão do PR sem trocar o checkout implantado:

```sh
cd ~/sandboxes/agent/projects/catus-os-m5 && git fetch -q origin feat/g4-homologation &&
  git show origin/feat/g4-homologation:deploy/g4.sh > ~/catus-g4.sh && bash ~/catus-g4.sh --repo "$PWD"
```

Duração típica: 20–30 min na primeira vez (baixa a imagem fixada do Playwright, ~2 GB, e constrói as imagens). Espaço livre necessário no Docker: ~8 GB. Saída: `~/catus-g4/<data>-<sha>/REPORT.md` (diretório 0700, fora do repositório), código de saída 0 somente com GO.

| Estágio                   | O que faz                                                                                                                                                                                                                                                                                                     | Escreve em                                                                    |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| A. Instalação real        | `deploy/catus.sh verify` (sem `--recreate`), foto do cluster e contagens antes/depois, idade do último backup, frontend servido = build do SHA testado                                                                                                                                                        | nada (somente leitura)                                                        |
| B. Suíte isolada          | Bun (unidade/integração), Playwright journeys (4 papéis) e quality (visual, axe, responsivo, teclado, estados, desempenho), typecheck, formatação e orçamento de bundle, em contêiner `--network none` da imagem fixada, PostgreSQL interno descartável, OIDC simulado do harness                             | só o contêiner, removido ao final                                             |
| C. Instalação descartável | Imagens de produção do SHA no projeto `catus-g4`: saúde, HTTPS/CA, cabeçalhos, Origin, sessão, papéis sem privilégio, contêineres endurecidos, M2/M5 desligados, backup cifrado, restauração idêntica (contagem + md5 por tabela), arquivo adulterado rejeitado, recriar, `down`/`up`, reinício do PostgreSQL | diretório temporário próprio; `down` sem `-v` e remoção do diretório ao final |

Proteções do executor: recusa root; a configuração descartável é conferida antes de subir (projeto `catus-g4`, imagens `catus-g4-*`, nenhum volume nomeado, dados em diretório temporário, nenhum caminho de segredo real, porta livre); variáveis `CATUS_*` do shell são descartadas; nunca roda `update`, `migrate`, `backup`, `restore-test` ou `admin-bootstrap` na instalação real; nunca usa `down -v`, `volume rm` ou `prune`; não lê cookies, tokens nem conteúdo de tabelas reais. Opções: `--sha`, `--skip-real`, `--skip-suite`, `--skip-disposable`, `CATUS_G4_PORT` (padrão 3543, só 127.0.0.1).

Smoke diário (rápido, somente leitura): `deploy/g4.sh --skip-suite --skip-disposable`.

## Entrega autovalidada (toda mudança futura)

| Etapa                | Gate objetivo                                                                                   | Onde                                        |
| -------------------- | ----------------------------------------------------------------------------------------------- | ------------------------------------------- |
| Implementar + testar | `npm test`, `npm run check`, `npm run format:check`                                             | agente, local                               |
| Construir            | `npm run build`, `npm run perf:budget`                                                          | agente + CI `validate`                      |
| UI/UX                | `npm run test:quality` (baselines exatas, axe WCAG 2.2 AA, 5 larguras, teclado)                 | CI `quality` (renderizador fixado)          |
| Segurança            | testes negativos Bun (CSRF, Origin, papéis, organização, cota), `verify` no estágio C           | CI `validate` + `G4 homologation rehearsal` |
| Desempenho           | orçamentos de bundle e runtime em `perf-budget.json`                                            | CI `validate` + `quality`                   |
| Revisão independente | revisão do diff por um revisor sem contexto do autor (humano ou agente), achados tratados no PR | PR                                          |
| PR + CI              | `validate` e `quality` obrigatórios (ruleset); `G4 homologation rehearsal` verde                | GitHub                                      |
| Aprovação            | proprietário autoriza merge explicitamente; mudanças críticas nunca são promovidas sozinhas     | humano                                      |
| Deploy + smoke       | `deploy/catus.sh update` no SHA aprovado, depois `deploy/g4.sh` → GO                            | proprietário, no host                       |

Falha em qualquer etapa: registrar a evidência (log/relatório do G4 ou artefato do CI), diagnosticar, corrigir a causa e reexecutar. Proibido: mascarar falhas, relaxar orçamentos sem justificativa registrada ou aprovar baselines visuais sem revisão humana das imagens (fluxo em [QUALITY.md](QUALITY.md)).

Rollback: `git checkout --detach <SHA anterior> && deploy/catus.sh update` quando não houver migration nova; com migration nova, restaurar o backup feito pelo `update` (HOMOLOGATION.md §6).
